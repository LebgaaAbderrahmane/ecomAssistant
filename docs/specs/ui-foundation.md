# Spec: UI foundation

- **Status:** proposed
- **Related:** `docs/REWORK_PLAN.md` Phase 4, [ui-screens.md](ui-screens.md), issue #50
- **Audience:** `front/` contributors

## 1. Problem

The current dashboard is a generic SaaS template with no system behind it:

- Four radii with no rule (`rounded-md`, `rounded-lg`, `rounded-xl`, `rounded-full`).
- Nine type sizes, many arbitrary (`text-[13px]`, `text-[11px]`, `text-[10px]`).
- Contrast failures at the token level: `#9ca3af` on white is 2.54:1, `#64748b` on `#0f172a` is 3.75:1.
- 0 `aria-label` on 46 buttons; clickable `<div>` overlays; no focus trap; no reduced-motion support.
- Every page re-implements fetch, loading, error, cursor, and selection state, and re-declares `Order`, `Customer`, `Product` interfaces.
- No error boundary. One render error blanks the app.
- i18n exists but `index.html` is fixed to `lang="fr"`, no `dir` switching, physical layout utilities, hardcoded French strings.

The visual identity is also absent: green accents on white cards is what every dashboard looks like. The product is an AI employee on WhatsApp for Algerian COD shops. The UI should feel like a dispatch desk, not a generic admin panel.

## 2. Goal

A token-driven, accessible, RTL-ready foundation with a small set of primitives, one data layer, and a shell that can host the reworked screens. No page in Phase 5 may invent its own spacing, colors, table, or fetch logic.

## 3. Design direction: dispatch desk

**Concept.** The merchant runs a shop; the dashboard is the dispatch desk. The first question is never "what is my revenue", it is "what needs me now". The Overview is a queue, not a KPI wall.

**Signature elements.**

- A queue-first Overview with a "needs attention" list.
- A live "agent pulse" strip: confirmed today, waiting on customer, escalations, last activity. Compact, textual, not four identical cards.
- Hairline ledger tables with tabular numbers.
- A persistent command bar with global search (`⌘K`) and agent status.

**Avoid.** Gradients, glassmorphism, decorative shadows, giant hero numbers, emoji icons, dashboard card grids that all look the same.

## 4. Tokens

Defined once in `front/src/styles/tokens.css` as CSS variables, mapped into `tailwind.config.js`. No hardcoded hex in components.

### Color

| Token | Light | Use |
|---|---|---|
| `--canvas` | `#F5F7F4` | app background |
| `--surface` | `#FFFFFF` | cards, tables, panels |
| `--surface-sunken` | `#EEF2EE` | wells, code, inactive tabs |
| `--ink` | `#10201B` | primary text |
| `--ink-muted` | `#5C6B65` | secondary text (≥ 4.5:1 on canvas and surface) |
| `--ink-faint` | `#6E7C76` | metadata only, never body (≥ 4.5:1) |
| `--line` | `#DDE4DF` | borders, dividers |
| `--line-strong` | `#C3CEC7` | input borders, focus-adjacent |
| `--brand` | `#0B6B4F` | primary action, active nav |
| `--brand-strong` | `#084C39` | hover/pressed |
| `--brand-soft` | `#E4F1EB` | selected row, subtle fill |
| `--signal` | `#B54708` | waiting, needs attention |
| `--signal-soft` | `#FDF0E4` | signal background |
| `--danger` | `#B42318` | destructive, failed |
| `--danger-soft` | `#FDECEA` | danger background |
| `--success` | `#067647` | confirmed, sent |
| `--success-soft` | `#E7F4EC` | success background |
| `--info` | `#175CD3` | informational |
| `--info-soft` | `#EAF1FD` | info background |

Rules:

- Every text/background pair used in the app is listed in `docs/specs/contrast.md` (generated by a script) with its ratio.
- `--ink-faint` is metadata only; never below 12px; never the only signal.
- Status color is semantic and identical across pages: confirmed = success, pending = signal, cancelled/failed = danger, shipped = info.
- Dark mode is a token swap, not a second stylesheet. No component may branch on theme.
- No color used to carry meaning alone: pair with icon or label.

### Type

- UI: **IBM Plex Sans** (Latin), **IBM Plex Sans Arabic** (Arabic).
- Numeric/IDs/phones/tracking/timestamps: **IBM Plex Mono**, `font-variant-numeric: tabular-nums`.
- Scale: 12, 13, 14, 16, 20, 24, 32, 40.
  - 12/1.4 — metadata, table headers, badges
  - 13/1.5 — dense UI, secondary rows
  - 14/1.5 — body, inputs, table cells
  - 16/1.5 — emphasized body, section intros
  - 20/1.3 — card titles, drawer titles
  - 24/1.25 — page titles
  - 32/1.2, 40/1.1 — only auth/landing/empty-state headlines
- Weights: 400, 500, 600. No 700 for body.
- Minimum 12px for anything a user must read. No 10px or 11px text.
- Line length 60–75ch for prose.

### Space, radius, elevation, motion

- Space scale: 4, 8, 12, 16, 20, 24, 32, 40, 48, 64.
- Radius: `4px` inputs/badges, `6px` buttons, `10px` cards/panels, `14px` drawers/modals. Nothing else.
- Elevation: borders by default. Shadow only for popover, dropdown, drawer, modal:
  - `--shadow-pop`: `0 4px 12px rgb(16 32 27 / 0.08)`
  - `--shadow-drawer`: `0 12px 40px rgb(16 32 27 / 0.16)`
- Motion: 120ms hover/press, 180ms popover, 240ms drawer. `ease-out` only. No bounce, no page-load choreography.
- `prefers-reduced-motion: reduce` disables transforms and non-essential transitions globally.

## 5. Layout and shell

- Rail: 240px, collapsible to 64px on desktop, overlay on mobile.
- Command bar: 56px, sticky. Page title left; global search, agent status, notifications, language, theme, avatar right.
- Content: max 1440px, 24px gutters, 32px section spacing.
- Rail order: Overview, Inbox (unread count), Orders, Catalog, Customers, Escalations. Bottom: Billing, Settings. No hardcoded plan card.
- Landmarks: `<nav>`, `<main>`, `<header>`, skip link to `#main`.
- Mobile: bottom-safe padding, 44px targets, drawer for nav, cards instead of tables.

## 6. Primitives

Build on Radix behavior, styled with tokens. Do not ship default shadcn visuals.

**Inputs:** Button, IconButton, Input, Textarea, Select, Combobox, Checkbox, Radio, Switch, Field (label + hint + error), Form.

**Surfaces:** Card, Panel, Section, Divider, Badge, StatusBadge, Avatar, Tooltip, Popover, DropdownMenu, Dialog, Drawer, Tabs, Toast, Banner, EmptyState, Skeleton, Progress.

**Data:** DataTable (sorting, selection, sticky header, column visibility, density), Pagination, FilterBar, BulkBar, Stat, Timeline, CommandPalette.

**Navigation:** PageHeader, Toolbar, Breadcrumbs, SidebarItem.

Rules:

- Every primitive has: default, hover, focus-visible, active, disabled, loading, error where applicable, RTL, dark.
- Icon-only buttons require `aria-label`. The prop is typed as required for `IconButton`.
- Dialogs and drawers use Radix for focus trap, escape, return focus, and `aria-modal`.
- Tables: `<caption>` (can be visually hidden), `<th scope>`, `aria-sort`, keyboard row activation, selection via checkbox with label.
- Toasts use `aria-live="polite"`; errors use `role="alert"`.
- Forms: label always associated, error linked with `aria-describedby`, `aria-invalid`, no placeholder-as-label.
- Loading uses skeletons for content and spinners only for actions.

## 7. Data layer

- TanStack Query for all server state. No `useEffect` fetch in pages.
- One typed API client generated from the OpenAPI spec (`back/src/config/swagger.yaml`) or from shared zod schemas. No hand-written `interface Order` in pages.
- Query keys: `['orders', filters]`, `['order', id]`, `['conversations', filters]`, etc. Mutations invalidate precisely.
- Shared hooks: `useOrders`, `useOrder`, `useCustomers`, `useProducts`, `useConversations`, `useEscalations`, `useAgentConfig`, `useNotifications`.
- Cursor pagination normalized in one helper; pages never parse cursors.
- Optimistic updates only for low-risk toggles (agent enabled, notification read). Destructive actions confirm first.
- Errors: one `ApiError` type, one error surface (banner or toast), retry only for idempotent reads.
- Global `ErrorBoundary` per route with a reset action. Suspense boundaries per route section.
- Routes lazy-loaded; initial bundle target < 250KB gzip.

## 8. i18n and RTL

- Namespaces stay, but every user-visible string comes from a locale file. No French literals in TSX.
- `index.html` gets `lang` and `dir` set at runtime from the active locale; Arabic sets `dir="rtl"`.
- Layout uses logical utilities (`ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`). No `left-0` / `ml-[250px]`.
- Numbers, currency, dates, relative time via `Intl`:
  - `Intl.NumberFormat(locale, { style: 'currency', currency: 'DZD', maximumFractionDigits: 0 })`
  - `Intl.DateTimeFormat(locale, { dateStyle: 'medium' })`
  - `Intl.RelativeTimeFormat(locale, { numeric: 'auto' })`
- Arabic numerals: use the locale default; do not hand-format.
- Font swap per locale via `:lang(ar)`.
- Pseudo-locale test (`ar-XB`) in CI to catch missing keys and clipped text.

## 9. Accessibility baseline

Target WCAG 2.2 AA.

- Contrast: all text pairs ≥ 4.5:1; large text ≥ 3:1; UI boundaries ≥ 3:1.
- Keyboard: every action reachable; visible `:focus-visible` ring (2px brand, 2px offset); no focus traps outside modals.
- Skip link, landmarks, one `<h1>` per page, ordered headings.
- Icon buttons named; images have alt or are decorative.
- No click handler on a non-interactive element without `role`, `tabIndex`, and key handling. Prefer `<button>`.
- Reduced motion respected.
- Zoom to 200% without loss; reflow at 320px.
- axe in CI: 0 critical/serious on shell and each screen.

## 10. Acceptance criteria

- [ ] Tokens are the only source of color, type, radius, spacing, and motion. `grep` for hex in `front/src/**/*.tsx` returns none.
- [ ] Every text pair in the app passes WCAG AA; the contrast table is generated and checked in CI.
- [ ] Type scale has no size below 12px; no arbitrary `text-[Npx]` outside the scale.
- [ ] Radii limited to the four tokens.
- [ ] ~30 primitives exist, documented on `/design`, each with all states and RTL.
- [ ] `IconButton` requires `aria-label` at the type level.
- [ ] Shell implements rail, command bar, skip link, landmarks, mobile drawer.
- [ ] No page calls `fetch` directly; all data goes through TanStack Query hooks and the typed client.
- [ ] No page re-declares a resource type.
- [ ] Route-level error boundary and suspense skeletons exist; a thrown render error does not blank the app.
- [ ] Routes are lazy-loaded; initial JS < 250KB gzip.
- [ ] Switching to Arabic sets `dir="rtl"`, swaps font, mirrors layout correctly, and uses `Intl` for numbers/dates.
- [ ] No hardcoded French string in TSX.
- [ ] `prefers-reduced-motion` disables non-essential motion.
- [ ] axe: 0 critical/serious on shell and `/design`; keyboard-only run of login → dashboard → orders passes.
- [ ] Lighthouse mobile: performance ≥ 90, accessibility 100 on the shell.
